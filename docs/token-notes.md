## Процедура выдачи токена (implicit flow, вручную)

Факты из доки Яндекс ID (`yandex.ru/dev/id/doc/ru`, разделы «Получение токена вручную»
и «Время жизни токена»):

- страница согласия показывается **один раз** на пару «приложение + аккаунт»; дальше та же
  ссылка отдаёт токен молча. Согласие сбрасывается только отзывом доступа на
  `id.yandex.ru/personal/data-access`; смена пароля / «выйти на всех устройствах» отзывают
  токены, но не согласие — перевыдача снова без экрана;
- токен и срок жизни приходят в redirect-URL после `#`:
  `#access_token=…&expires_in=<секунд>`;
- типы токенов: «продлеваемый» (живёт «не менее 1 года», продлевается при каждом
  использовании) и «ограниченный» (фиксированный срок по правам). Что выпало для disk-прав —
  записать ниже.

Шаги:

1. Открыть `https://oauth.yandex.ru/authorize?response_type=token&client_id=<CLIENT_ID>`.
2. Разрешить доступ; из адресной строки скопировать `access_token` и `expires_in`.
3. Проверить (не вставляя токен в чат/git):
   `curl -s -H "Authorization: OAuth $TOKEN" "https://cloud-api.yandex.net/v1/disk/" | head -c 400`
   — ожидаем JSON с `total_space`, `used_space`, `user.login`, не 401.
4. Если `expires_in` оказался неудобно коротким — перейти на explicit-flow (ниже).

> **Не вариант:** «пароль приложения» (id.yandex.ru) — он аутентифицирует только WebDAV
> (`webdav.yandex.net`). REST API (`cloud-api.yandex.net`) принимает исключительно OAuth
> и отвечает 401 на Basic-аутентификацию. Решение зафиксировано 18.09.2026.

## Explicit-flow (если implicit-токен оказался короткоживущим)

Серверный токен: `GET https://oauth.yandex.ru/authorize?response_type=code&client_id=…` →
обменять `code` на `https://oauth.yandex.ru/token` (POST: `grant_type=authorization_code`,
`code`, `client_id`, `client_secret`) → в `.env` сервера лежат `YD_TOKEN` + `YD_REFRESH_TOKEN`
+ `YD_CLIENT_ID` + `YD_CLIENT_SECRET` (600); адаптер сам обновляет access-токен по
`grant_type=refresh_token`. Телефонному токену explicit-flow не нужен — перевыдача вручную
приемлема.
